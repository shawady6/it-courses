Module 1 — مدخل: البصمة وأجهزة ZKTeco

1.1 ZKTeco إيه؟

ZKTeco شركة صينية متخصصة في الـ Biometrics (بصمة إصبع، وجه، كف، قزحية) وأنظمة الحضور والانصراف Time & Attendance وكنترول الأبواب Access Control. أجهزتها منتشرة جدًا في مصر والمنطقة، وبتلاقيها بأسماء تجارية متعددة (بعض الشركات بتبيعها بعلامة تانية).

1.3 رسم توضيحي: شكل عام لجهاز بصمة حضور

1.4 البصمة شغالة إزاي؟

  • Fingerprint template: الجهاز مش بيخزن صورة البصمة، بيستخلص منها Minutiae (نقاط مميزة زي Ridge ending وBifurcation) ويخزنها كـ Template صغير (حوالي مئات Bytes). عملية عكسية لرجوع الصورة الأصلية غير ممكنة عمليًا، لكن الـ Template نفسه بيانات حساسة وتتعامل بخصوصية.
  • Verification (1:1): المستخدم يدخل رقمه/كارته ← الجهاز يقارن بصمته بتمبلت واحد. أسرع وأدق.
  • Identification (1:N): المستخدم يحط إصبعه وبس ← الجهاز يقارن مع كل التمبلتس. أبطأ كل ما العدد يزيد.
  • FAR (False Accept Rate: قبول شخص غلط) وFRR (False Reject Rate: رفض شخص صح). تزويد الحساسية بيقلل واحد ويزود التاني. Threshold بتحدده الإعدادات.
  • مستشعرات: Optical (بتصوّر بالضوء، أرخص، حساسة للأتربة والبصمات المتبقية) وCapacitive/Semiconductor (أدق وأقاوم). والـ Liveness (فحص إن الإصبع حي) في موديلات معينة.

1.5 نصايح تسجيل بصمة ممتاز

  • سجّل أكتر من إصبع (على الأقل 2–3، من إيدين مختلفين) عشان لو الإصبع اتجرح.
  • الإصبع مركزه على الحساس، ضغط متوسط، ومسطح (مش بس الطرف). كرر التسجيل 3 مرات بنفس الوضعية.
  • إيد نظيفة وجافة (الرطوبة والزيوت والمواد الكاشطة بتضرّ جودة البصمة). عمال البناء/الورق/الكيماويات ممكن تبصمهم ضعيفة → اتجه للكارت أو الوجه.
  • سجّل بنفس طريقة الاستخدام اليومي (الواقف نفسه).

1.6 أسئلة مراجعة

1) الجهاز بيخزن صورة البصمة؟لا، بيخزن Template (Minutiae) مش صورة.
2) الفرق بين 1:1 و 1:N؟1:1 بيقارن مع Template واحد بعد ID/كارت. 1:N بيقارن مع الكل.
3) إيه FAR و FRR؟قبول غلط / رفض غلط.
4) ليه نسجل أكتر من إصبع؟لتفادي مشاكل الجروح أو الضعف.

Module 3 — التركيب والتوصيل (Power / Network / Door)

3.1 مكان التركيب

  • ارتفاع الجهاز حوالي 1.2–1.4 متر لمركز الشاشة/الحساس (راجع دليل الموديل). بعيد عن الشمس المباشرة (بتأثر على Optical والكاميرا) وعن المياه/الأتربة.
  • جنب الباب (في Access Control) بحيث الموظف يقف براحة. وفي مداخل المصانع: قارئ مغطى ضد المطر لو برا.
  • كابل شبكة قريب أو PoE، وكهرباء مستقرة (UPS لو الكهرباء بتقطع).

3.2 الكهرباء

البندالتفاصيل
جهد الجهازغالبًا 12V DC (1–3A حسب الموديل) أو PoE. راجع الملصق.
القفل (Lock)يفضّل Power supply منفصل للقفل (12V/24V) مش من نفس مصدر الجهاز، وإلا الـ Reset يحصل عند فتح القفل (Back EMF).
Diodeركّب Diode/Surge على القفل (1N4007) لحماية الريليه.
Fail-safe vs Fail-secureFail-safe (Magnetic lock): بيقفل بالكهرباء وبيفتح لما تقطع (مناسب للطوارئ/الحريق). Fail-secure (Electric strike): بيفضل مقفول لو الكهرباء قطعت (مناسب للأمان). قرّر حسب كود الحريق.

3.3 رسم توصيل باب (Standalone Access Terminal)

  • Relay output: أطراف NO (Normally Open) COM NC (Normally Closed). الجهاز بيقفل الريليه لفترة Lock Drive Time (مثلاً 3–5 ثواني).
  • Door sensor (Reed switch): بيقول الباب مفتوح/مقفول (لتنبيه Door Left Open).
  • Exit button: زر خروج من جوه.
  • Wiegand: بروتوكول بسيط (D0/D1) بين قارئ ولوحة. RS485 أأمن وأبعد (لحد حوالي 1200م).
  • Alarm: Tamper (كسر الجهاز)، Duress (إجبار).

3.4 الشبكة

  • كابل Cat5e/Cat6 لحد 100م. وصّل بـ Switch. يفضّل VLAN منفصل لأجهزة البصمة.
  • IP ثابت (Static) أو DHCP Reservation. ما تخليش الـ IP يتغير لأن البرنامج متعرّف عليه بالـ IP.
  • لو Wi-Fi: التغطية مستقرة وكلمة سر قوية. الكابل أفضل للاعتمادية.

Lab 2 — تشغيل الجهاز لأول مرة بسيط

  1. وصّل الكهرباء والشبكة، وانتظر الإقلاع. اضبط Date & Time (مهم جدًا).
  2. اتأكد إن الـ Switch بيدي Link LED. جرّب ping بعد ما تحط IP (Module 5).
  3. سجّل أول Admin: Menu → User Mgt → New User بـ Role = Administrator (لو الجهاز فيه Administrators فاضيين، أي حد يدخل Menu).
  4. سجّل مستخدم تجريبي وبصمة. اعمل Check-in وشوف الشاشة.
  5. (Access) وصّل ريليه وLED تجريبي بدل القفل وتأكد إنه بيشتغل عند البصمة.
متتعاملش مع Mains (220V) إلا بكهربائي. اختبر القفل بمصدر منفصل وبمقاومة/ليد قبل القفل الحقيقي.

أسئلة مراجعة

1) ليه Power Supply منفصل للقفل؟القفل بيسحب تيار وبيعمل Back-EMF فيعيد تشغيل الجهاز.

4.2 إضافة مستخدم

  1. Menu → User Mgt → New User.
  2. User ID (PIN): رقم الموظف (فريد). ابقاه ثابت ومتطابق مع رقم الموظف في HR/البرنامج. (الأفضل أرقام بدون أصفار بادئة تتلخبط في Excel).
  3. Name: بالإنجليزي أفضل (بعض الأجهزة ما بتدعمش العربي على الشاشة). في ZKBio Time ممكن تكتبه عربي لكن الجهاز ممكن يعرضه رموز.
  4. Privilege: Normal User أو Administrator (بيدخل Menu) أو Enroller.
  5. سجّل FP (Fingerprint: 3 مرات للإصبع) أو Card (مرر الكارت) أو Password أو Face.
  6. اختياري: Verification mode خاص بالمستخدم، Group/Time zone (Access).

4.3 Duplicate Punch و Punch State

  • Duplicate Punch Period: فترة (بالدقائق) يتجاهل بعدها البصمة المكررة (مثلاً 1–5 دقايق) لتفادي تسجيلات مزدوجة.
  • Punch State: Check-In / Check-Out / Break-Out / Break-In / OT-In / OT-Out. في الأجهزة اللي فيها أزرار F1–F4 بتختار الحالة قبل البصمة. كتير بيستخدموا Auto-State switch بالجدول الزمني. في الواقع كتير من الأنظمة بتستنتج In/Out من ترتيب البصمات (راجع Module 7 و13).
  • Work Code: كود اختياري مع كل بصمة (سبب/مهمة).

4.5 Backup واستعادة

  • خد Backup للمستخدمين والتمبلتس بشكل دوري: من البرنامج (Sync/Export) أو من USB Manager أو بالكود (pyzk: get_users / get_templates). Attendance بعد ما تتمسح من الجهاز مبترجعش.

Lab 3 — مستخدمين + بصمة + تقرير سريع بسيط

  2. ضبط Duplicate Punch = 1 دقيقة. بصّم 3 مرات متتالية وشوف Attendance Search.

import csv, datetime

def parse_attlog(path):
    rows = []
    with open(path, encoding="utf-8", errors="ignore") as f:
        for line in f:
            p = line.rstrip("\r\n").split("\t")
            if len(p) < 2:
                continue
            pin = p[0].strip()
            ts = datetime.datetime.strptime(p[1].strip(), "%Y-%m-%d %H:%M:%S")
            status = p[2].strip() if len(p) > 2 else ""
            verify = p[3].strip() if len(p) > 3 else ""
            rows.append((pin, ts, status, verify))
    return rows

for r in parse_attlog("ATTLOG.dat")[:10]:

from zk import ZK, const

zk = ZK('192.168.1.201', port=4370, timeout=5, password=0,

conn = None
try:
    conn = zk.connect()

import sqlite3, datetime, threading
from flask import Flask, request, Response

app = Flask(__name__)
DB = "adms.db"
lock = threading.Lock()
ALLOWED_SN = set()       # حط Serial Numbers المسموحة، فاضي = اقبل الكل (للتجارب فقط)

def db():
    c = sqlite3.connect(DB); c.row_factory = sqlite3.Row; return c

with db() as c:
    c.executescript("""
    CREATE TABLE IF NOT EXISTS punches(sn TEXT, pin TEXT, ts TEXT, status INT, verify INT, raw TEXT,
        PRIMARY KEY(sn,pin,ts));
    CREATE TABLE IF NOT EXISTS commands(id INTEGER PRIMARY KEY AUTOINCREMENT, sn TEXT,
        cmd TEXT, sent INT DEFAULT 0, result TEXT);
    CREATE TABLE IF NOT EXISTS devices(sn TEXT PRIMARY KEY, last_seen TEXT, ip TEXT);
    """)

def text(s): return Response(s, mimetype="text/plain")

def check(sn):
    if ALLOWED_SN and sn not in ALLOWED_SN: return False
    with lock, db() as c:
        c.execute("INSERT INTO devices VALUES(?,?,?) ON CONFLICT(sn) DO UPDATE SET last_seen=?, ip=?",
                  (sn, datetime.datetime.now().isoformat(), request.remote_addr,
                   datetime.datetime.now().isoformat(), request.remote_addr))
    return True

@app.route("/iclock/cdata", methods=["GET", "POST"])
def cdata():
    sn = request.args.get("SN", "")
    if not check(sn): return text("ERROR"), 403
    if request.method == "GET":                      # Handshake
        return text(f"GET OPTION FROM: {sn}\nATTLOGStamp=None\nOPERLOGStamp=9999\n"
                    "ErrorDelay=30\nDelay=10\nTransTimes=00:00;14:05\nTransInterval=1\n"
                    "TransFlag=TransData AttLog OpLog\nRealtime=1\nEncrypt=0\n")
    table = request.args.get("table", "")
    body = request.get_data(as_text=True)
    if table == "ATTLOG":
        n = 0
        with lock, db() as c:
            for line in body.splitlines():
                p = line.strip().split("\t")
                if len(p) < 2: continue
                st = int(p[2]) if len(p) > 2 and p[2].isdigit() else None
                vf = int(p[3]) if len(p) > 3 and p[3].isdigit() else None
                cur = c.execute("INSERT OR IGNORE INTO punches VALUES(?,?,?,?,?,?)",
                                (sn, p[0], p[1], st, vf, line))
                n += cur.rowcount
        print(f"[{sn}] ATTLOG {n} new")
    else:
        print(f"[{sn}] {table}: {body[:300]}")        # OPERLOG / USERINFO / غيره: سجّل وشوف
    return text("OK")

@app.route("/iclock/getrequest")
def getreq():
    sn = request.args.get("SN", "")
    if not check(sn): return text("ERROR"), 403
    with lock, db() as c:
        r = c.execute("SELECT * FROM commands WHERE sn=? AND sent<3 ORDER BY id LIMIT 1", (sn,)).fetchone()
        if not r: return text("OK")
        c.execute("UPDATE commands SET sent=sent+1 WHERE id=?", (r["id"],))
    return text(f"C:{r['id']}:{r['cmd']}")

@app.route("/iclock/devicecmd", methods=["POST"])
def devicecmd():
    sn = request.args.get("SN", "")
    body = request.get_data(as_text=True)
    with lock, db() as c:
        for line in body.splitlines():
            kv = dict(x.split("=", 1) for x in line.split("&") if "=" in x)
            if "ID" in kv:

db = sqlite3.connect("attendance.db")
rows = db.execute("SELECT pin, ts FROM punches ORDER BY pin, ts").fetchall()

DEDUP = dt.timedelta(minutes=3)
by_day = defaultdict(list)
for pin, ts in rows:
    t = dt.datetime.strptime(ts, "%Y-%m-%d %H:%M:%S")
    lst = by_day[(pin, t.date())]
    if lst and t - lst[-1] < DEDUP:
        continue                      # بصمة مكررة
    lst.append(t)

for (pin, day), times in sorted(by_day.items()):
    first, last = times[0], times[-1]
    worked = (last - first) if len(times) > 1 else dt.timedelta(0)
    status = "MISSING_OUT" if len(times) == 1 else "OK"
    print(pin, day, first.time(), last.time(), worked, status)

14.4 Best Practices

  • PIN ثابت ومنظم (نفس رقم HR) + دليل تسمية للأجهزة والأماكن.
  • IP ثابت + توثيق (جدول الأجهزة: SN، IP، Firmware، الموقع).
  • مزامنة وقت (NTP/ZKBio Time) وتحقق شهري.
  • Backup دوري (مستخدمين + تمبلتس + DB) وتجربة Restore.
  • UPS للأجهزة الحرجة. Battery backup لو متاح.
  • تدريب الموظفين على البصمة الصحيحة، وبديل (كارت/وجه) لمن لديهم مشاكل.
  • لا تعدّل Logs يدويًا بدون Audit.

Appendix D — سيناريوهات Troubleshooting

فكّر الأول، وبعدين افتح الحل.
1) البصمات بتظهر على الجهاز لكن ZKBio Time مش شايفها.الجهاز Offline أو غير Authorized، أو Cloud Server Setting على بورت غلط. شوف حالة الجهاز في البرنامج وSN، وجرّب تغيير الـ Address لـ IP مباشر بدل Domain.
2) كل البصمات بتتسجل قبل الوقت الصح بساعتين.Timezone/DST مختلف بين الجهاز والسيرفر. ضبط الوقت بعد تثبيت Timezone، وتأكد إنك مش بتحوّل مرتين.
3) سكريبت pyzk بيشتغل مرة ويفشل مرة.اتصالات متزامنة (البرنامج + سكربت) على نفس الجهاز، أو جهاز Wi-Fi ضعيف، أو Timeout قصير. نسّق الوصول وزوّد Timeout.
4) الجهاز "Disabled" والموظفين مش قادرين يبصموا.سكريبت قبل ما يعمل enable. أعد التفعيل من الجهاز أو سكربت، وصحّح بـ try/finally.
5) ADMS: الجهاز بيعمل GET كل ثانيتين لكن مش بيبعت ATTLOG.مفيش بصمات جديدة، أو Stamp عند السيرفر بيمنع إعادة الإرسال، أو الإعدادات (TransFlag) في الـ Handshake مش بتفعّل إرسال Attlog. سجّل Request/Response كامل وقارن.
6) ADMS: الأوامر بترجع Return=-1002.صيغة غير صحيحة: استخدم DATA UPDATE USERINFO بفواصل TAB حقيقية، وتحقق من أسماء الحقول (Pri/Privilege) حسب جهازك.
7) موظف بصمته ما بتتقبلش فجأة.جرح/رطوبة/حساس متسخ. نضّف الحساس، سجّل إصبع تاني، أو كارت مؤقت.
8) نفس البصمة بتتسجل مرتين.Duplicate Punch Period = 0 أو إرسال مزدوج (Push + Pull). ضبط الفترة ومفتاح فريد في DB.
9) تقرير بيقول "Absent" وهو حاضر.مفيش PIN مطابق (Mapping)، أو الوردية غلط، أو البصمة خارج Check-in window. راجع Raw.
10) جهاز بعد انقطاع الكهرباء بيرجع للوقت الافتراضي.بطارية الساعة (RTC) ضعيفة. غيّر البطارية وفعّل مزامنة تلقائية.
11) القفل بيفتح وبيقفل بعشوائية / الجهاز بيعيد التشغيل عند الفتح.مصدر الطاقة مشترك مع القفل. افصل القفل على Power Supply ومعاه Diode.
12) سيرفر ADMS شغال محلي، والجهاز في فرع ما بيوصلوش.NAT/Firewall/VPN. تأكد إن الجهاز يوصل للسيرفر على البورت (curl من شبكة الفرع).
